# VibeCast

Локальная музыка с телефона — на компьютере. Android-приложение раздаёт библиотеку
по Wi-Fi, десктопное приложение находит телефон, показывает обложки, исполнителей,
альбомы и играет треки **на ПК** через mpv.

```
Android (Ktor)  ── HTTP + Range + SSE ──►  PC (Tauri + React + SQLite)
  MediaStore                                  каталог, поиск, очередь
  Foreground Service                           mpv (IPC), дисковый кэш
  mDNS + токен                               mDNS-обнаружение
```

Звук не стримится в реальном времени: ПК скачивает файл по HTTP (с Range) и
воспроизводит его локально. Это даёт мгновенный повтор из кэша и устойчивость к
пропаже телефона во время проигрывания.

## Возможности MVP

- Автоматический поиск телефона в локальной сети по mDNS (`_vibecast._tcp`).
- Ручное подключение по URL + Bearer-токену, если mDNS заблокирован.
- Полный каталог: обложки, исполнители, альбомы, поиск, сортировка, виртуализация
  списка (20 000 треков без просадок UI).
- Воспроизведение через mpv: play/pause, следующий/предыдущий, seek, громкость,
  прогресс, очередь.
- Кэширование на диск: первый play — поток, повторный — с диска; индикатор
  «Стрим/Кэш».
- Обновление каталога по SSE без перезапуска ПК-приложения.
- Офлайн-режим: каталог и кэш доступны, когда телефон выключен.
- Чистый первый запуск: никаких демо-треков — каталог появляется только после
  подключения телефона. Явное отключение очищает каталог на ПК.
- Токен обязателен для всех ручек, кроме `/health`; в логи и mDNS не попадает.

## Структура репозитория

```
android/            Android-приложение (Kotlin, Compose, Ktor CIO)
  app/              UI, MediaStore, Foreground Service, mDNS, токен
  shared/           протокол, маппинг каталога, Ktor-сервер, JUnit-тесты
desktop/            Tauri 2 + React + TypeScript + Vite
  src/              UI, состояние, dev-мок (только VITE_MOCK=1)
  src-tauri/        Rust: SQLite, HTTP/SSE, mDNS, mpv IPC, кэш
scripts/            mock-server.mjs (протокол без телефона), генератор иконок
docs/               PLAN.md, TESTING.md
DECISIONS.md        архитектурные решения и компромиссы
```

## Требования

- **Android:** Android 8.0+ (API 26), разрешение на доступ к аудио. Для сборки —
  Android Studio либо JDK 17–21 + Android SDK 35 + Gradle 8.11 (wrapper в repo).
- **ПК:** Windows 10/11, Linux или macOS; Node.js 20+, Rust 1.80+, WebView2
  (Windows), системные зависимости Tauri 2. mpv 0.37+.
- Телефон и ПК в одной локальной сети; клиентская изоляция (AP isolation) на
  роутере должна быть выключена.

## Сборка Android

Самый простой путь — открыть `android/` в Android Studio и собрать `app`.

Через командную строку:

```bash
cd android
./gradlew :app:assembleDebug        # Windows: gradlew.bat
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

Нужны `JAVA_HOME` (JDK 17–21) и `ANDROID_HOME`. Файл `android/local.properties` с
`sdk.dir=...` создаётся локально и не коммитится.

> **Windows + кириллица в пути.** Gradle-тест-воркер падает с
> `ClassNotFoundException`, если путь к проекту содержит кириллицу. Создайте
> ASCII-джанкшен и собирайте через него:
>
> ```bat
> mklink /J C:\vibecast "C:\путь\к\WMusic"
> cd C:\vibecast\android
> gradlew.bat :app:assembleDebug
> ```

Установка на телефон: `adb install -r app-debug.apk` или скопировать APK вручную.

### Первый запуск Android

1. Выдайте разрешение на музыку (Android 13+ — «Аудио и видео»).
2. Разрешите уведомления — без них foreground-сервис работает, но статус не виден.
3. Нажмите **Запустить сервер**. Приложение просканирует MediaStore и покажет
   адрес, количество треков, токен и кнопку копирования ссылки для ПК.
4. По желанию отключите оптимизацию батареи кнопкой в приложении — это повышает
   шансы, что сервис переживёт долгий сон экрана.
5. Для нового трека: скопируйте файл в память телефона, дождитесь индексации
   MediaStore или нажмите **Пересканировать**.

Токен показывается на экране (скрыт по умолчанию). Кнопка «Копировать ссылку с
токеном» кладёт в буфер `http://<ip>:<port>/#token=...` — эту ссылку можно вставить
в поле «Адрес телефона» на ПК, и токен подхватится автоматически. QR-кода нет:
у ПК-приложения нет камеры, а mDNS и ссылка решают задачу быстрее.

## Сборка и запуск ПК-приложения

Установите mpv:

```powershell
winget install shinchiro.mpv          # Windows
```

```bash
sudo apt install mpv                  # Debian/Ubuntu
brew install mpv                      # macOS
```

Сборка:

```bash
cd desktop
npm install
npm run tauri dev                     # разработка
npm run tauri build                   # релиз + установщик
```

Готовые артефакты: `desktop/src-tauri/target/release/bundle/` (MSI/NSIS, deb/AppImage,
dmg — в зависимости от ОС). Если системный упаковщик недоступен, используйте
`npm run tauri build -- --no-bundle` — бинарник появится в
`desktop/src-tauri/target/release/`.

Если mpv установлен в нестандартное место, укажите путь в **Настройки → mpv** или
задайте переменную `VIBECAST_MPV`. Приложение также ищет mpv в `PATH` и типовых
каталогах установки.

### Подключение

1. Запустите сервер на телефоне.
2. Откройте VibeCast на ПК и нажмите **Сменить телефон**.
3. Выберите найденное устройство. Для первого подключения введите токен с экрана
   телефона либо вставьте скопированную на телефоне ссылку целиком (включая
   `#token=...`) в поле «Адрес телефона». При повторном подключении ПК сам
   подхватит сохранённый токен, в том числе если телефон получил новый IP.
4. Двойной клик по треку — воспроизведение. Повторный запуск уже прослушанного
   трека идёт из кэша, в том числе без телефона.

Данные ПК:

- каталог и настройки — `%APPDATA%\com.vibecast.desktop\vibecast.db` (Windows),
  `~/.local/share/com.vibecast.desktop/` (Linux), `~/Library/Application Support/`
  (macOS);
- кэш — `%LOCALAPPDATA%\vibecast\audio` и `...\covers` (Windows),
  `~/.cache/vibecast/` (Linux/macOS).

Кэш можно посмотреть и очистить в настройках приложения.

## Проверка протокола без телефона

В репозитории есть mock-сервер, реализующий контракт Android (8 треков, Range,
обложки, SSE):

```bash
node scripts/mock-server.mjs
```

Подключитесь к `http://127.0.0.1:8765` с токеном `demo-token-123`. Для проверки
Range:

```bash
curl -i -H "Authorization: Bearer demo-token-123" \
  -H "Range: bytes=100-200" http://127.0.0.1:8765/audio/0101010101010101010101010101010101010101
```

Ожидается `206 Partial Content`, `Content-Range: bytes 100-200/352844` и
`Content-Length: 101`.

Для проверки вёрстки в браузере можно явно включить демо-источник:

```bash
VITE_MOCK=1 npm run dev
```

Без `VITE_MOCK=1` браузерная страница показывает ошибку запуска, а не фальшивый
каталог. В обычном приложении Tauri демо-треков нет никогда.

## Ограничения и безопасность

- **HTTP без TLS.** Токен защищает от случайного доступа, но трафик можно
  прослушать в недоверенной сети. Не используйте приложение в публичных Wi-Fi.
- Токен на ПК хранится в SQLite без шифрования (см. D9); в логи не пишется.
- Нет QR-кода: ПК-приложение не умеет сканировать камерой, поэтому на телефоне
  показываются адрес, токен и готовая ссылка для копирования.
- Нет gapless между разными треками: каждый трек загружается отдельным `loadfile`.
- Нет repeat/shuffle, редактирования метаданных, облака и аккаунтов.
- mDNS может блокироваться файрволом Windows или роутером (AP isolation) —
  используйте ручное подключение. На телефоне удерживается MulticastLock и
  выполняются повторные попытки регистрации при смене Wi-Fi; при первом запуске
  разрешите приложению частные сети в файрволе Windows.
- Проверка на реальном Android-устройстве и 30-минутный тест экрана в этом
  окружении не выполнялись (нет устройства/эмулятора); это отмечено в TESTING.md.

Учебный MVP. Музыкальные файлы и обложки принадлежат их правообладателям; проект
не включает музыку.
