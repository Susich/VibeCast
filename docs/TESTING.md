## 7. Что не проверено и почему

1. **Установка и внутренности Android.** USB-debugging выключен, поэтому не
   проверены чистая установка APK, permission-flow, foreground-сервис,
   уведомление, 30 минут с выключенным экраном и mDNS-регистрация на телефоне.
   HTTP-каталог, обложки и воспроизведение на реальном телефоне проверены (§11).
2. **Тайминги первого play.** На реальном телефоне холодный старт mpv дал ~2,2 с до
   видимой позиции 0:01; цель ≤0,8 с не подтверждена. Повтор из кэша быстрый, но
   инструментально не замерен.
3. **20 000 треков.** Виртуализация и SQL-поиск реализованы, но нагрузочный прогон
   на 20k записей не выполнялся; реальная библиотека — 366 треков.
4. **Установщики.** MSI/NSIS собираются; запуск установщиков не выполнялся, чтобы
   не менять систему. Проверен release-бинарник.
5. **Кроссплатформенность.** Проверено только на Windows 11. Код для Linux/macOS
   (пути, Unix socket, команды открытия каталога) написан, но не запускался.
6. **mDNS на реальном телефоне.** ПК не увидел сервис этого телефона; работал
   LAN-скан. Причина не установлена без logcat.

## 9. Исправления после первого запуска на телефоне

Пользователь прислал экран с ошибкой `getServiceName(...) must not be null` при
запуске сервера.

**Причина.** В `NsdPublisher.start()` внутри `NsdServiceInfo().apply { ... }`
выражение `serviceName = serviceName.take(60)` читало ещё не заполненное поле
самого `NsdServiceInfo` (оно было `null`), а не имя из конструктора. Kotlin
вставлял проверку `getServiceName(...)`, и запуск падал.

**Исправление.**
- Параметр переименован в `preferredName`; имя безопасно нормализуется через
  `trim().ifEmpty { "VibeCast" }`.
- Логирование `info.serviceName` стало null-safe.
- Ошибка mDNS теперь не останавливает HTTP-сервер: телефон остаётся доступен по
  URL и токену, UI показывает предупреждение.

**ПК без демо-треков.**
- Демо-источник UI включается только явным `VITE_MOCK=1` вне Tauri; обычная
  браузерная страница и release-приложение показывают пустой каталог.
- Явное «Отключить» теперь очищает SQLite-каталог, сессию и останавливает mpv.
- Тестовые данные (mock-каталог, 4 WAV и 8 обложек) удалены с этой машины.

**Проверено после исправления.**
- `:shared:test :app:assembleDebug` — BUILD SUCCESSFUL, APK пересобран.
- `cargo test --lib` — 6/6; `npm run build` — успешно; `npm run tauri build` —
  MSI и NSIS пересобраны.
- Release-бинарник на чистом профиле: 0 треков, «Подключите телефон».
- Подключение к mock: 8 треков; «Отключить»: 0 треков; повторный запуск: 0.
- SQLite после теста: `tracks=0`, `server=0`, `catalog_version=0`.

**Не проверено на момент этого раздела.** Реальная mDNS-регистрация на телефоне
после переустановки APK не проверялась. Позже телефон стал доступен по Wi-Fi:
LAN-скан находит его, но mDNS-сервис по-прежнему не виден (§11); установка нового
APK всё ещё требует USB-debugging.

## 10. Удаление QR и усиление mDNS

Пользователь указал, что QR-код на телефоне бессмысленен: у ПК-приложения нет
камеры. Также попросил сделать так, чтобы ПК находил телефон рядом и подключался.

**Что изменено.**
- Экран Android больше не рисует QR и не зависит от ZXing. Вместо него карточка
  «Подключение с ПК»: адрес, кнопка «Копировать ссылку с токеном» и подсказка
  вставить ссылку в поле адреса на ПК.
- `NsdPublisher`: ASCII-нормализация имени сервиса (кириллица/пробелы могут ломать
  DNS-SD), до 3 попыток регистрации с паузой, остановка «висящей» регистрации.
- `ServerService`: `MulticastLock` + разрешение `CHANGE_WIFI_MULTICAST_STATE`;
  `ConnectivityManager.NetworkCallback` перерегистрирует mDNS при смене Wi-Fi;
  ошибка mDNS по-прежнему не останавливает HTTP-сервер.
- Desktop: новая команда `connect_saved` переиспользует сохранённый токен и
  переподключается к найденному по mDNS телефону с новым IP. Клиент автоматически
  пробует это при событии discovery; при ошибке показывает toast. Явное
  «Отключить» очищает сессию, поэтому авто-подключения после него нет.
- Тексты в UI больше не предлагают QR; в документации QR упоминается только как
  осознанно отсутствующая возможность.

**Проверено.**
- `:shared:test :app:assembleDebug` — BUILD SUCCESSFUL; APK пересобран, 23 JUnit
  теста без изменений.
- `cargo fmt --all`, `cargo check --lib` — успешно; `cargo test --lib` — 6/6
  (включая выбор приватного адреса mDNS); `npm run build` — strict TypeScript +
  Vite успешно (235.29 kB JS / 72.83 kB gzip, 33.29 kB CSS).
- Нативный прогон Tauri (CDP, mock-сервер + `publish_mdns`):
  - чистый профиль: 0 треков, «Подключите телефон»;
  - mDNS-список показывает `VibeCast Mock`; ручное подключение по
    `http://127.0.0.1:8765` + токен загружает 8 треков;
  - клик по найденному устройству с сохранённым токеном переключает сессию с
    `127.0.0.1:8765` на `192.168.1.11:8765` без ввода токена;
  - авто-переподключение: mock на 8765 остановлен (UI «телефон недоступен»,
    каталог сохранён), затем поднят mock на 8766 и publisher с новым портом —
    приложение само подключилось к `192.168.1.11:8766`, 8 треков;
  - воспроизведение после переподключения работает, трек доигрывает и
    переключается на следующий.
  - `publish_mdns` теперь принимает `VIBECAST_MDNS_PORT` и
    `VIBECAST_MDNS_NAME`, чтобы воспроизводить смену адреса/порта телефона.
- Пересобранный release (`npm run tauri build`, MSI 3.61 MiB / NSIS 2.72 MiB)
  запущен с сохранённой сессией: 8 треков из SQLite, кэшированный трек играет;

## 11. Проверка на реальном телефоне: один клик и LAN-поиск

Пользователь попросил: треки должны запускаться одним кликом (а не двойным),
автопоиск устройства должен работать, и попросил проверить на подключённом
телефоне.

**Телефон.** Samsung SM-A546E, Wi-Fi `192.168.1.13`, сервер на `:8765`,
`/health` → `catalogVersion=7`, `trackCount=366`. USB-debugging выключен
(`adb devices` пуст), поэтому APK не переустанавливался, logcat и permission-flow
